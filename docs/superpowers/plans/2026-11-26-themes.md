# Themes (v0.6.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A site gets its look from a theme: a folder `themes/<key>/` of Blade templates chosen in the admin, with
templates per content type, taxonomy and single record, its own layouts, code, data and settings, falling back to
Hata's built-in views.

**Architecture:** `Hata\Themes\ThemeRepository` reads manifests from the themes folder; the scoped `Themes` service
decides lazily which theme a request uses (the stored one, or a previewed one) and puts it in use (view and
translation namespace `theme`, an autoloader for its `src/`, `functions.php`, `boot()`), all behind a guard that
turns any failure into "broken, use the built-in views". `ThemeViews` answers the first existing view of a chain
for each kind of page; the public controllers ask it instead of naming `hata::site.*`. Settings live in one JSON
row per theme; assets are answered by a route and, optionally, a link in `public/`.

**Tech Stack:** PHP 8.4, Laravel 13, Blade, Livewire 4.4 SFC + Flux 2.21 free (admin pages only), Pest 5 on Testbench,
PHPStan level 7.

**Spec:** `docs/superpowers/specs/2026-11-26-themes-design.md` (read it whole, including "Settled after the builder
check"; it is the binding authority).

## Global Constraints

- A theme never edits or overrides a Hata file; Hata writes into `themes/` only through `make:theme`.
- Public pages stay plain Blade: no Livewire, no Flux, no admin JavaScript (decision 59).
- **No query and no folder scan on a public request** because of themes: the active key and the settings come from
  the rows `SiteSettings::stored()` already holds; themes are listed only on the admin page. A test asserts the query
  count of a record page with a theme equals the count without one.
- A broken or missing theme never takes the site down: any `Throwable` while loading or booting it is logged once
  and the built-in views are used.
- With no theme chosen the public site renders exactly as before this plan, except Task 10's colour change; a
  site's overrides in `resources/views/vendor/hata/site/…` keep working.
- The admin's colour scheme never reaches a public page (the user's ruling).
- The theme key is the folder name: `^[a-z0-9]+(-[a-z0-9]+)*$`. Anything else is not a theme.
- Themes folder: `config('hata.themes.path')`, default `base_path('themes')` (tests point it at fixtures).
- Every new admin string in `resources/lang/en` and `uk`; `TranslationParityTest` passes. Flux free only; no new
  Composer or npm dependency. Shipped file names ASCII. A shipped migration is never edited.
- Rebuild and commit `dist/` after any change to `resources/css`/`resources/js` or a Tailwind class new to the views.
- The suite passes on SQLite, MySQL and PostgreSQL, one database at a time; no `pest --parallel`.
- Admin screens are shown to clients: reuse the existing card, table and form markup; they go through the user's
  browser pass before the release.
- Every change to routes, permissions, forms or rules updates its spec in the same commit (`docs/specs/themes.md`
  is created in Task 1 and grows with each task).

## Review Focus

1. **A path outside `assets/`**: `/themes/nyam/../theme.php`, `/themes/nyam/%2e%2e/src/Theme.php`, a dot file, a
   `.php` file inside `assets/`, a symlink leaving the folder — all 404, nothing is read (Task 5).
2. **The active theme's folder is deleted or its manifest throws**: every public page still answers 200 with the
   built-in views, one log line, and the themes page says why (Tasks 2, 8).
3. **A guest during someone's preview**: a request without a session cookie starts no session, sees the active
   theme, and its response carries no cookie; a signed-in user without `themes.manage` who forges the session key
   sees the active theme (Task 9).
4. **A forged template**: posting a template the theme does not offer for that type is a validation error; a
   stored key the theme in use lacks is kept on save and skipped at render (Task 4).
5. **A theme key that is not a key** (`Nyam`, `..`, `a/b`) in the setting, the preview session, the asset route
   and the admin routes: treated as no theme / 404, never joined into a path (Tasks 1, 5, 8, 9).

      public ?string $author; public ?string $screenshot; /** @var class-string<Theme>|null */ public ?string $class;
