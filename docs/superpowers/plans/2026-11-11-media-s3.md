# Media library Part 5: S3-compatible storage

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Media files on any S3-compatible store, configured from the admin, served to pages by direct CDN URLs, with resumable moves between disks.

**Architecture:** `SiteSettings` maps new `media_s3_*` keys over `filesystems.disks.s3.*` and `media.disk`; a `StorageConnectionTest` action checks a configuration. A `MediaPaths`/`MediaWriter` pair decides object paths (versioned on cloud disks) and write options, and a `media_pending_deletions` table defers removal of replaced cloud objects. `Media::url()`/`thumbUrl()` return direct public URLs for cloud raster images; `MediaController` streams SVG, redirects the rest, and supports Range. Disk moves reuse the optimization run mechanics (decision 48) through a shared batch base.

**Tech Stack:** Laravel 13 (Flysystem S3 v3 adapter), Livewire 4 SFC, Flux 2.21 free, Pest 5.

**Spec:** `docs/superpowers/specs/2026-11-11-media-s3-design.md` (approved 2026-11-11, including the new dependency), on top of `docs/specs/media.md` and `docs/specs/site-settings.md`.

## Global Constraints

- New dependency: `league/flysystem-aws-s3-v3` only (approved). No other packages.
- A disk is "cloud" when its configured driver isn't `local` (`App\Support\Media\MediaDisks::isCloud(string $disk): bool`); every rule below keys off that, never off the name `s3`.
- Cloud object paths carry the version: `media/{Y/m}/{key}-v{version}.{ext}`, `media/thumbs/{key}-v{version}.webp`, `media/originals/{key}-v{version}.{ext}`; local paths stay as today.
- Replaced cloud objects (rebuild, move) are deleted after 7 days by a cleanup that needs no worker or cron; deleting a media row deletes its objects at once; local files are deleted at once as today.
- Direct URL only for cloud raster images and their thumbnails when a public URL is set: `{public_url}/{prefix?}/{path}?v={version}`. SVG is always streamed by the app with the CSP sandbox + `nosniff`. Documents/other files: 302 to a signed `temporaryUrl` (1 hour) with `ResponseContentDisposition` = the real name. No public URL → raster images 302 to a signed URL too. Redirects carry `Cache-Control: no-cache, must-revalidate, max-age=0`.
- Objects are written with `ContentType` and `CacheControl: public, max-age=604800`; no ACL option.
- Settings: storage `local`/`s3`, endpoint, region, bucket, access key, secret key (encrypted, never shown back, empty keeps stored), path-style, public URL, path prefix (the disk `root`). Saving `s3` requires a passing connection test with the values being saved. Changing bucket/endpoint/prefix/public URL while rows are on `s3` warns; clearing the S3 connection while any row is on `s3` is refused.
- Moves: copy (streams) → verify sizes → switch `disk` + paths in a transaction with a version guard → old objects to pending deletions (cloud) or deleted after commit (local). Failure leaves the row as it was and removes partial copies.
- Shared hosting: no worker, no SSH required; streams for copies; 128 MB memory.
- Tests: no network — `Storage::fake('s3')` (note: a faked disk is a local adapter; tests must still exercise the cloud branches by keeping `filesystems.disks.s3.driver = s3` in config and using `Storage::disk('s3')->buildTemporaryUrlsUsing()` for signed URLs). One optional MinIO integration test, skipped unless `MEDIA_S3_INTEGRATION=1`.
- Every string in `lang/en` + `lang/uk`; specs (`media.md`, `site-settings.md`) updated in the same commit; CLAUDE.md decision 50 at the end (never touch the Boost block). Flux free only.
- Before each commit: `vendor/bin/pint --dirty --format agent`, `composer types:check`, affected tests; whole suite on SQLite; MySQL for migrations. Messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A page rendered before a crop on a cloud disk keeps showing the old image for at least 7 days (old versioned object still there), and the new render points at the new object (Task 2 test).
2. Switching `media.disk` to `s3` while old rows stay on `local`: both kinds render correct URLs side by side (Task 3 test).
3. A move that fails halfway (copy of the thumbnail throws) leaves the row on the old disk with every old file intact and no partial objects on the target (Task 5 test).
4. A wrong secret / bucket in the form: "Test connection" names the failure and saving `s3` is refused; the stored working settings stay (Task 1 test).
5. SVG on the cloud disk opened by its URL gets the sandbox CSP and `nosniff` and is never a redirect to the bucket (Task 3 test).
