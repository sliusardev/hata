## Starter kit structure

- **Livewire SFC pages:** `resources/views/pages/**/⚡name.blade.php`, namespace `pages::` (Livewire's default `component_namespaces`, config not published). The ⚡ emoji prefix is on.
- **Full-page routes:** `Route::livewire('settings/profile', 'pages::settings.profile')->name(...)`. Layout: `layouts::app` → `resources/views/layouts/app/sidebar.blade.php`.
- **Page titles:** set with the `#[Title('...')]` attribute, which takes a literal string, so it can't be translated. Translated titles go through `render()`/`->title(__('...'))`; see the decisions below.
- **Auth views:** `resources/views/pages/auth/*.blade.php` (plain Blade, rendered by Fortify via `FortifyServiceProvider::configureViews`).
- **Settings:** `routes/settings.php` (profile, appearance, security), sub-navigation in `pages/settings/layout.blade.php`.
- **Toasts:** `Flux::toast(...)` with `<flux:toast.group>` persisted in the sidebar layout.
- **Existing Actions:** `app/Actions/Fortify/*` (Fortify contracts, method names set by Fortify). `app/Concerns/*ValidationRules.php` are validation-rule traits.
- **AppServiceProvider:** `Date::use(CarbonImmutable::class)`, `DB::prohibitDestructiveCommands()` in production, `Password::defaults()` (strict in production, `null` otherwise).
- **Tests:** Pest, SQLite `:memory:` (phpunit.xml), `RefreshDatabase` for Feature tests. `composer test` = pint --test + phpstan + tests. CI (`.github/workflows/tests.yml`) runs `composer setup` + `composer ci:check`.
- **No `lang/` directory** before stage 1. About 106 unique `__('Literal')` strings in the starter kit.
- `.ai/` contains only `mcp/mcp.json`; there is no `.ai/rules`.
- A local MySQL is available via Herd (`mysql` binary) for running the suite against MySQL.

## Flux free vs Pro

Flux 2.21 free ships `table` (with `sortable` columns, `paginate`), `pagination`, `toast`, `modal`, `select` (native), `checkbox`, `badge`, `callout`, `dropdown`. Because `flux:table` is in the free package, we use it instead of a custom table component. Pro-only components (e.g. `flux:select variant="listbox"`, date pickers, `flux:autocomplete`) must not be used.

## Decisions

Each decision gives its date and its reason. Add new ones at the end.

1. **CLAUDE.md is committed.** It was removed from `.gitignore`; `AGENTS.md`, `.ai/` and `boost.json` stay local (generated by Boost).
2. **Email verification stays disabled** (no `Features::emailVerification()`, `User` doesn't implement `MustVerifyEmail`). The admin route group still carries the `verified` middleware, so it starts working once verification is enabled. The "email verified" checkbox only sets `email_verified_at`. Reason: shared hosting may not have working mail.
3. **The dashboard moves into the admin area:** `/admin`, route `admin.dashboard`, behind `can:admin.access`. `/settings/*` (profile, language, security, appearance) stays available to any authenticated user. After login (Fortify `home`), a user without `admin.access` is sent to `profile.edit` instead of a 403 page.
4. **Use `flux:table`** (it's in Flux free) instead of a custom Blade table component.
5. **Registration toggle:** `config/admin.php` → `registration_enabled` (env `ADMIN_REGISTRATION_ENABLED`, default `false`). `Features::registration()` is added to Fortify's features only when it's enabled.
6. **Page titles are translation keys.** `#[Title('settings.profile.title')]` holds a key, and `partials/head.blade.php` translates it with `__($title)`. A title passed already translated (`:title="__('...')"`) still works, because `__()` returns a missing key unchanged.
7. **Vendor literals without JSON files.** Fortify, laravel/passkeys and Flux call `__('Some English sentence')`. The project has no `lang/*.json`, so `App\Support\Translation\VendorTranslations` maps these literals to PHP keys (`auth.vendor.*`, `common.flux.*`) through `Lang::handleMissingKeysUsing()` in `AppServiceProvider`. When a package update adds a new literal, add it to that map and to both languages.
8. **Toast after a redirect:** `App\Support\Toast::success()/danger()` flashes to the session, and `<x-flash-toast />` in the app layouts fires Flux's `toast-show` event on the next page. `Flux::toast()` stays for actions that don't redirect. This is the single toast approach for the whole admin.
9. **Language page:** `settings/language` (`language.edit`), a separate settings page. After saving, a full redirect (no `wire:navigate`) re-renders `<html lang>` in the new language. `User` implements `HasLocalePreference`, so emails such as password reset go out in the user's language.
10. **`welcome.blade.php` is not translated.** It's Laravel's demo landing page and will be replaced by the frontend themes stage.
11. **spatie/laravel-permission 8.4**, teams off, guard `web`. Spatie clears its own cache when roles or permissions change (`RefreshesPermissionCache`, `givePermissionTo`/`syncPermissions`), and `permissions:sync` clears it explicitly.
12. **Fortify `home` stays `/dashboard`.** That route (`dashboard`) only redirects: users with `admin.access` go to `admin.dashboard`, everyone else to `profile.edit`. This covers every Fortify flow (login, 2FA, passkeys, registration) without overriding Fortify response classes.
13. **DatabaseSeeder no longer creates "Test User".** That factory needs Faker (a dev dependency, missing after `composer install --no-dev`) and sets the password `password`. Instead the seeder runs `permissions:sync`, then `RoleSeeder`, then creates the super admin from `config('admin.initial_admin')` (`ADMIN_NAME/EMAIL/PASSWORD`) if it doesn't exist yet. Running it repeatedly is safe.
14. **RoleSeeder only adds permissions** (defaults in `config/permissions.php` → `roles`, `*` = all), so changes made by an administrator survive a reseed. The `admin` role picks up new permissions on every seed.
15. **`App\Enums\SystemRole`** holds the names of the system roles. `App\Models\Role::displayName()` returns `roles.names.<name>` for system roles and `label` for custom ones.
16. **`CreateSuperAdmin` is an action without an actor** (used by the CLI and the seeder). Actions with an actor (`CreateUser` and others) arrive in step 4.
17. **Artisan command output is in English.** It's for developers, not the admin UI.
18. **Starter registration tests are skipped** while registration is off (`skipUnlessFortifyHas`). `RegistrationToggleTest` covers that registration is off by default and that a new user gets no role.
19. **Laravel Boost appends its guidelines to this file** on `composer update/require` (block `<laravel-boost-guidelines>`). Don't edit that block; Boost regenerates it.

## Conventions

- **Translations:** PHP files only in `lang/en` and `lang/uk`. Keys are snake_case and nested by page/block. Every new key goes into both languages in the same change. `tests/Feature/Localization/TranslationParityTest.php` checks file/key parity, empty values and placeholders, that every `__('group.key')` used in `app/` and `resources/views/` exists, and that every vendor-map target exists.
- **Languages:** `config('app.available_locales')`. The `SetLocale` middleware (web group) applies `users.locale` or `config('app.locale')`.
- **Permissions:** declared in `config/permissions.php` (`groups`) or by modules via `PermissionRegistry::register()`. Run `php artisan permissions:sync` (`--prune` deletes stale ones). Labels go in `lang/*/permissions.php`; a test checks that every permission has a translation. Code checks permissions (`can('users.edit')`), never role names; the only exception is super-admin in `Gate::before`.
- **Admin routes:** `routes/admin.php`, prefix `admin`, names `admin.*`, middleware `auth, verified, can:admin.access`.
- **Tests:** `seedRolesAndPermissions()` (tests/Pest.php), and the factory states `User::factory()->withRole('editor')` and `->withPermissions([...])`.
